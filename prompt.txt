Data model and security (guidance)

- Use these tables (you will provide the complete SQL with RLS policies):
  - profiles:
    - id uuid primary key references auth.users(id) on delete cascade
    - username text unique not null (lowercased)
    - full_name text null
    - avatar_url text null
    - created_at timestamptz default now()
    - RLS: authenticated users can select all; users can update only their own row. Create a trigger to auto-insert a profile on user sign-up.
  - conversations:
    - id uuid primary key default gen_random_uuid()
    - member_one uuid not null references auth.users(id)
    - member_two uuid not null references auth.users(id)
    - pair_key text generated always as (
      case when member_one < member_two then member_one::text || ':' || member_two::text
           else member_two::text || ':' || member_one::text
      end
    ) stored unique
    - created_at timestamptz default now()
    - RLS: select allowed only if auth.uid() is a member; insert allowed only if auth.uid() = member_one and member_two != auth.uid(); updates not needed; delete none.
  - messages:
    - id bigint primary key generated always as identity
    - conversation_id uuid not null references conversations(id) on delete cascade
    - sender_id uuid not null references auth.users(id)
    - body text not null check (length(body) > 0 and length(body) <= 2000)
    - created_at timestamptz default now()
    - indexes: (conversation_id, created_at)
    - RLS: select allowed only to conversation members; insert allowed only if sender_id = auth.uid() and auth.uid() is a member of the conversation.
- Realtime:
  - Ensure messages table is added to the Realtime publication (supabase_realtime). Provide SQL to enable this.

Architecture guidance

- Next.js App Router with src/ structure. Suggested top-level folders:
  - src/app: routes (auth, chat, api), global styles, layout
  - src/components: UI components (user list, chat window, message list, forms, header)
  - src/lib: supabase client, types, helpers
  - src/hooks: e.g., useAuth, useRealtimeMessages
  - supabase/: SQL schema/migrations/policies files (checked into repo)
- Keep business rules in helpers/hooks; keep UI presentational components slim.
- Use TypeScript types for Supabase rows and common DTOs.
- Keep env var naming consistent:
  - NEXT_PUBLIC_SUPABASE_URL
  - NEXT_PUBLIC_SUPABASE_ANON_KEY
- Do not expose the service role key to the browser. Avoid needing it by using RLS correctly. For “ensure conversation,” implement client logic: find existing by pair_key; if not found, insert; if unique violation occurs, reselect.
